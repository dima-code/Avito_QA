# README.md

## Описание проекта
Данный репозиторий содержит решение тестового задания к отбору на стажировку в Avito по направлению QA Spring 2026. 

В нем представлены:

**Task_1** - Поиск багов

**Task_2.1** - Тесты API

### Дерево проекта

```bash
.
├── README.md
├── Task_1
│   ├── bags.png
│   └── solution.md
└── Task_2.1
    ├── API_Automation.py
    ├── BUGS.md
    ├── TESTCASES.md
    ├── pyproject.toml
    └── requirements.txt
```


Проверяются следующие ручки:
- `POST /api/1/item` — создание объявления
- `GET /api/1/item/{id}` — получение объявления по id
- `GET /api/1/{sellerID}/item` — получение всех объявлений продавца
- `GET /api/1/statistic/{id}` — получение статистики по item id

Тесты написаны с использованием `pytest` и `requests`.


## Требования
Для запуска необходимы:
- Python 3.10 или выше
- установленный `pip`

## Полная инструкция по запуску автотестов

### 1. Скопировать репозиторий с GitHub

```bash
git clone https://github.com/dima-code/Avito_QA
```

### 2. Перейти в домашнюю директорию проекта
```bash
cd ~/Avito_QA
```

### 3. Создать виртуальное окружение
```bash
python3 -m venv venv
```

### 4. Активировать виртуальное окружение
Для macOS/Linux:
```bash
source venv/bin/activate
```
Для Windows:

```bash
.\venv\Scripts\activate
```


### 5. Обновить pip
```bash
python3 -m pip install --upgrade pip
```

### 6. Установить зависимости
```bash
python3 -m pip install -r Task_2.1/requirements.md
```

### 7. Запустить автотесты
```bash
pytest -v Task_2.1/API_Automation.py
```

## Что покрывают автотесты
Автотесты проверяют:
- успешное создание объявления
- получение объявления по id
- получение всех объявлений продавца
- получение статистики по item id
- граничные значения `sellerId`
- отсутствие идемпотентности у `POST`
- обязательность полей
- невалидные типы входных данных
- пустое тело запроса
- обработку несуществующих id
- обработку невалидного `sellerId`
- пустую выборку объявлений продавца
- базовую проверку времени ответа
- проверку `Content-Type`
- обработку длинного значения `name`


## E2E-проверки
В проекте реализованы сквозные API-тесты, покрывающие последовательные пользовательские сценарии:
- создание объявления → получение объявления по id
- создание нескольких объявлений одного продавца → получение списка объявлений продавца
- создание объявления → получение статистики по item id

## Особенности реализации
- все проверки выполнены через `assert`
- тесты независимы друг от друга
- каждый тест использует собственные тестовые данные
- для предотвращения пересечений используется генерация уникальных `sellerId` в диапазоне `111111–999999`
- тесты воспроизводимы и не зависят от порядка выполнения
